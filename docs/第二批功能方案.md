# 第二批功能方案：本地课表与系统入口

状态：用户已授权实施，当前进度与未完成项见《第二批实施记录.md》。以下保留产品目标，不代表各项目已验收。教务导入继续暂缓。

## 目标

把演示界面推进为本地可日常使用的课表，并通过原生桌面组件、锁屏组件、Live Activity / 灵动岛减少打开 APP 的次数。保持免费、本地优先，不为这些功能先建自有服务器。

## 先决条件：第二批 A

1. SwiftData 本地保存，重新打开 APP 后数据仍在；演示数据与个人数据明确区分。
2. 完成课程添加、编辑、删除、单双周及指定周次；支持单次停课、补课、调课例外。
3. 使用真实日期、学期和作息计算课程实例，处理跨日、学期边界、周末与空课状态。学校课表使用明确的校园时区，不随旅行时区错误漂移。
4. 接入原生本地通知，支持提前量、逐课程开关；数据变更后撤销或重排受影响的提醒。
5. 提供学期与作息设置的真实保存，明确修改影响；采用版本化迁移，不覆盖个人数据。

验收：关闭重开仍有数据；课程修改、调停课后首页/周课表/提醒一致；无课不产生提醒。通知受权限、专注模式及系统设置影响，不承诺一定响铃。

## 桌面与锁屏组件：第二批 B（优先交付）

| 入口 | 首版内容 | 操作 |
| --- | --- | --- |
| 桌面小号 | 当前或下一节课、地点、开始/结束时间 | 点击打开对应课程 |
| 桌面中号 | 当前/下一节突出，后续 1–2 次课程，今日剩余数量 | 点击课程打开详情 |
| 桌面大号 | 当天课程时间线 | 后续按需求增加，首批不塞七天网格 |
| 锁屏矩形 | 课程名、教室、开始时间或课前倒计时 | 点击课程 |
| 锁屏圆形 | 距离开课的紧凑时间或课程进度 | 点击当前安排 |
| 锁屏行内 | 例如“10:00 大学英语 · B205” | 点击课程 |

首批推荐桌面小/中号、锁屏矩形/行内，圆形和大号随后补充。系统决定尺寸与布局，支持系统着色、深浅色和可用的透明样式，不自绘外壳，不强制锁屏显示蓝色。

状态：未建课表→引导添加；课前→下一节；上课→当前课程；当天结束→明确标明明天/下次上课日期；无后续课→明确空状态。长课程名与长教室名有紧凑显示，完整信息在 APP 中查看。

交互首版以准确跳转为主，不在小组件中放编辑表单、复杂周次菜单或误触风险较高的删除/停课操作。提醒开关可在后续评估 App Intents 后增加。

刷新：基于已知课程生成时间线，在开课、下课、跨日等边界提供条目；修改本地数据后请求重载。使用系统时间文本表现倒计时，不靠每秒后台唤醒。WidgetKit 的刷新受系统预算控制，不能承诺任意指定时刻绝对刷新；异常时不展示伪精确状态。

验收：锁屏、退出 APP、跨日、深浅色、系统着色、长文本、无课状态和课程变更后检查一致性；通过真机验证，不只交 SwiftUI 预览图。

## Live Activity 与灵动岛：第二批 C

可以使用官方 ActivityKit + WidgetKit；有灵动岛的支持机型显示岛上布局，无灵动岛机型按系统能力提供锁屏 Live Activity。锁屏小组件与锁屏 Live Activity 是两种不同入口，不相互替代。

### 建议设计

- 开关名称：“上课实时活动”，默认关闭，首次使用解释用途。
- 第一阶段允许在课程详情手动开始本次活动；先在用户真机验证整个生命周期。
- 验证后加入课前预定启动，例如提前 15 分钟，允许调整提前量。
- 紧凑岛：左侧课程符号，右侧紧凑时间；最小岛：简洁课程符号，避免完整课程名。
- 展开岛：课程名、教室、起止时间，以及与本次课程有关的操作。
- 锁屏活动：课程信息与课前/课中时间状态，尽量不展示教师或学号。
- 下课结束本次活动，不用全天常驻活动承载整周课表，不为保持占岛制造空活动。

### 用户明确的课程实时活动规则

目标：课前按设置提前出现，课中显示，课程结束自动退出；下课提醒可以独立关闭，允许用户主动结束。不能把“关闭下课通知”理解为让活动继续常驻。

#### 设置

- 上课通知开关与提前量。
- 课程实时活动开关；默认使用相同的课前提前量，避免重复设置，可在有明确需求后提供独立提前量。
- 下课提醒独立开关，建议默认关闭；支持到点提醒，提前几分钟提醒作为可配置方案保留。
- 手动结束本次活动只影响本次课程，不关闭下一节课的活动与通知，也不自动取消已开启的下课通知。

#### 生命周期

| 阶段 | 产品行为 |
| --- | --- |
| 进入课前提前量 | 显示即将开始的课程、地点与距离上课时间；按权限和用户设置发上课通知 |
| 正在上课 | 显示当前课程及下课时间；展开可查看下一节课程、时间和地点 |
| 下一节预提醒已到，当前课尚未结束 | 保留当前课主状态，补充下一节与换教室提示；不叠加本 APP 的多张活动抢占展示 |
| 课程最终结束 | 若开启下课提醒则按设置通知；无论是否提醒，都结束本次活动并移除展示 |
| 下一节已进入其课前窗口 | 将其作为独立课程活动承接；否则保持无活动，直到下次课前窗口 |
| 用户主动结束本次活动 | 记录本次结束意图，不在恢复 APP 或重新协调时反复拉回；下一次课程仍按原设置处理 |

系统在灵动岛上的收起手势不一定等于结束或移除锁屏 Live Activity。尊重系统交互，并提供明确“结束本次”的操作；不将岛暂时收起误判为用户永久关闭该功能。系统或用户移除后不强制重建同一个课程实例。

#### 连堂课与换课、换教室

- 同一课程实例、同一地点且属于连续教学安排：按一个连堂课程块处理，正常小课间不重复发开课通知、不反复上下岛，最终下课才退出。相隔半天或中间有其他课的同名课程不能合并。
- 相同地点但课程不同：新课程，名称、时间、教师和提醒计划都要切换，不能因为教室相同就继续算上一门课。
- 同一课程但地点改变：拆分地点阶段并提示换教室，不把课程身份相同等同于地点不变。
- 课程与教室均改变：显示下一课程、开课时间和新地点，并提示“下一节需换教室”。
- 地点缺失或无法可靠识别：提示“下一节地点待确认”，不猜测是否需要移动。只按已知地点判断，不凭空估计步行时间。
- 用稳定课程/实例标识和规范化地点判断，不仅比较课程名称或显示字符串。
- 调课、停课、删课后统一撤销或更新通知、活动计划和组件；检测课程冲突时不能悄悄覆盖。

验收案例：同课同教室连堂、同教室换课、同课换教室、跨楼换课、长课间与短课间、无下一课、地点缺失、跨日、用户手动移除、下课通知关闭、后台/锁屏时到下课边界。

#### 需要实机验证的关键点

“下课结束自动隐藏”是产品验收要求，尚未证明本地后台方案可以满足。必须验证到点结束操作的执行机制；普通倒计时到零、内容标记过期、结束后的延迟移除策略，都不能直接冒充已经实现了定时结束。先测本地官方机制；如不满足，再明确评估可选 APNs 服务及其网络条件，不擅自把要求降为“打开 APP 才结束”。

### 实现边界与验证顺序（技术验证）

苹果现有 API 提供预定开始 Live Activity 的能力，优先验证无需服务器的计划启动路线。不能把旧版“只能前台开始”的限制直接套用于目标系统，也不能未经编译与真机验证便承诺自动上岛可用。

具体先验证目标 SDK 的 API 可用性、权限、预定数量、重启/退出与系统限制，再决定可交付范围。只规划近期必要活动，打开 APP 和修改课表时重新协调计划，不为整个学期一次申请所有活动。

预定开始不等于后台代码会在所有课程边界准时执行。倒计时文本可以由系统显示，但课前→课中→下课的内容切换、结束与后续课程衔接需要单独验证。手动开始只是早期验证路径，不替代用户要求的自动生命周期；云端 APNs 作为必要时的可选方案评估，不先保证全自动。

Live Activity 有系统生命周期限制（官方文档目前说明活动最多保持活跃八小时），展示位置与优先级也由系统决定。灵动岛不是普通通知，不能靠一条本地通知自动执行任意启动代码，也不保证长时间独占岛上空间。

验收：检查紧凑/最小/展开/锁屏布局，实际锁屏和退到后台，验证计划启动、课程边界、更新、用户手动结束、权限关闭及调停课后撤销；对不支持灵动岛的机型提供合理表现。

## 共用数据与模块

- ScheduleCore：真实课程实例、时间规则与下一节计算，避免主 APP 与组件各算一套。
- Persistence：SwiftData 和迁移；主 APP 负责写入。
- SystemSnapshot：主 APP 在 App Group 中原子写入最小课程快照，组件只读，包含版本与生成时间；不将教务凭据放入共享快照。
- Widgets：WidgetKit 时间线、各尺寸与深链接。
- LiveActivities：本次课程活动状态、计划协调与结束。
- Notifications：独立的通知安排与权限状态。
- DesignSystem：系统语义色、间距和排版，遵守“选中系统蓝，常规操作黑白”；组件仍以系统渲染模式为准。

数据流：个人课程→统一实例计算→APP 页面、本地提醒、组件快照、实时活动。修改课程时统一协调这些输出，避免删课后组件与提醒仍显示旧课。

## 后续候选，不计入本批承诺

- 控制中心“查看下一节课”入口，快捷指令添加课程/打开今日。
- 本地备份导出/恢复，必要时优先于更多组件样式。
- 可选 iCloud 同步，等本地迁移与冲突规则稳定再做。
- Apple Watch 独立课表、考试安排等在实际使用反馈后决定。

## 发布与测试

会员资格激活后，配置正式可用的应用标识、App Group、Widget Extension 和 Live Activity 支持，通过 EAS 构建并上传 TestFlight，先仅供本人测试，不发布 App Store。

自动化测试重点覆盖周次、例外、课程边界、时区、下一节、快照和通知变更，不用布局实现细节充当测试。云端检查主 APP 与扩展同时编译。组件与实时活动的生命周期必须用真机验收。

建议交付顺序：A 本地核心与提醒 → B 桌面/锁屏组件 → C 手动 Live Activity 与计划启动验证。每阶段给出可复现结果；C 的自动化范围由实机结果决定。
