# 教务导入真机反馈修复（2026-11-03）

## 已确认问题

1. 真机打开青岛工学院显示 ATS 拦截。目录地址为 `http://jw.qit.edu.cn/jwglxt/xtgl/login_slogin.html`；公开 HTTP 页面实测返回 200，HTTPS 探测握手失败，没有使用账号登录。
2. 目录共 2862 条记录，原始等级 3 / 2 / 1 / 未评级分别为 87 / 1528 / 1246 / 1。它们是上游元数据，不是本 App 逐校验证结果。旧界面只显示前两类，并错误使用“已验证”“可用”的表述。
3. 原始目录包含无网址的“超星分享课表导入”，不应混作学校网页入口。当前界面按合法 HTTP(S) 入口计数，不把总记录数当作独立学校数。
4. 页面加载失败后提取按钮仍可点击；登录跳转取消旧导航可能弹出原始错误；`target=_blank` 未接入；仅提取顶层 HTML 会漏掉同源 iframe 的课表。
5. 文件界面声称支持 HTML，但读取后只尝试分享码和文本，未复用网页的 HTML 表格和内嵌 JSON 解析。

## 修复

- 目录中有 1086 条初始 HTTP 地址，且学校登录可能跳转到其他供应商域名。将最初的单校例外方案调整为 Apple 的 `NSAllowsArbitraryLoadsInWebContent`：兼容 WebKit 内的教务网页，不设置全 App `NSAllowsArbitraryLoads`，保留 URLSession 的默认 ATS；不添加信任挑战回调，不绕过证书验证。仅对用户选择的学校开启临时 WebView，会话数据仍为 nonPersistent。HTTP 页面显示简短连接提示。
- 删除“已验证／可用”数量和学校评级标签，保留教务入口数量与系统名称；明确收录不等于逐校实测。搜索结果达到上限时说明只显示前 60 个。
- 加载失败显示中文原因和重新加载；在页面成功加载前禁用提取。忽略正常的 URL 导航取消，新窗口 HTTP(S) 链接在原临时会话打开，进程终止后允许重试。
- 读取已加载的同源 frame，有遍历和大小上限；不读取跨域 frame，不再通过同步滚动循环声称触发懒加载。
- 网页和 HTML 文件共用内嵌 JSON、表格、可见文本回退解析。文本回退先移除脚本和样式。
- 增加入口计数、HTTP(S) 过滤、HTML 解析回归用例；上传前检查最终归档的主 App Info.plist，防止源码配置没有进入安装包。

Apple 官方配置说明：[NSAllowsArbitraryLoadsInWebContent](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowsarbitraryloadsinwebcontent)。后续 App Store 审核应说明：App 作为用户主动操作的多校教务网页容器，需要兼容第三方 HTTP 入口与跳转，原生请求仍保留 ATS，未持久化登录会话。配置例外不等于所有学校都能成功登录或导入。
