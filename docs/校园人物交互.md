# 校园人物与课表联动

日期：2026-10-31。人物动作由真实课程实例、当前时间和课前提前量决定，不随机切换。今日页固定使用同一位戴帽女生，保留用户确认的黑白手绘风格；伸展帧采用左手扶右手肘的姿态。

## 状态规则

| 课表状态 | 稳定姿态 | 进入状态或点击时的动作 |
| --- | --- | --- |
| 尚未进入首课提前量，或当天无课 | 坐着阅读 | 点击翻书 |
| 进入课前提前量，无需换教室 | 站着拿书 | 起身拿书、准备上课 |
| 进入课前提前量，前后教室明确且不同 | 站姿 | 收书、起身、短暂行走 |
| 正在上课 | 坐着阅读 | 坐下拿书；点击仅翻书 |
| 课间，尚未进入下一节提前量 | 坐姿休息 | 收书或坐下；点击小幅休息动作 |
| 当天课程全部结束 | 坐姿休息 | 收书、起身伸展、坐下；点击放松后仍回到休息姿态 |

正在进行的课程始终优先，不会因为下一节进入提醒窗口而提前行走。同教室或地点待定不推断换教室；行走表示课表提示，不表示已定位到用户位置。开关通知不会取消界面状态，提前量沿用用户的课前分钟设置。

状态直接读取应用使用的课程实例，停课、调课、补课、删除和时间设置变化都经现有实例生成流程反映。正常时钟由现有前台约 30 秒刷新驱动，回到前台立即刷新；这是界面动作，不承诺后台播放动画。

## 交互约束

- 正式页面只有符合当前课表状态的回应按钮；任意站坐、拿放书菜单仅保留在内部验证页。
- 打开过去或其他未来课程只查看详情，不更改人物状态；当前关联课程可触发同一个人物的合理回应。
- 首次打开直接显示当前姿态，不补播过去的动作。相同课表状态不会因时钟刷新反复播放。
- 课表状态变化优先于用户点击，取消旧动作，避免旧动画稍后覆盖新姿态。重复点击不并发；切后台停止播放并回到当前稳定姿态。
- 遵守系统减少动态效果，直接显示状态对应的稳定姿态。课程卡保留原生触感请求和轻微按压效果。
- 点击课程不会修改课程、完成状态、提醒或数据。

## 素材

原生 SwiftUI 播放 4×4 手绘动作图集，身体、手臂、腿和书本有逐帧变化，并非整图晃动。男生用于内部验证；女生前 15 帧继续读取原始图集，只有最后一帧读取修正图集，保留帽子、长发、条纹衣及帆布包。

插画兼容浅深背景，不整图反色。这是短动作序列，不是骨骼动画或物理仿真。生成与修正提示词见《校园人物动作素材说明》。
